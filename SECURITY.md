# Security Policy

Do not disclose security vulnerabilities in public GitHub issues, discussions,
or pull requests before they are addressed.

## Reporting

Report security issues **privately**.

**Human release blocker:** this repository does not yet publish a security
contact address or confirm that GitHub private vulnerability reporting is
enabled. Private security reporting instructions will be added before the
first public release.

Until that contact exists, do **not** file a public issue for a vulnerability.

## What to include

A useful report typically includes:

- Affected component (for example API, desktop client, document processing, auth)
- Steps to reproduce
- Impact (what an attacker or untrusted input could do)
- Relevant logs or configuration with **secrets removed**

Do **not** include passwords, API keys, tokens, private keys, session cookies,
or other secrets.

This project does not claim guaranteed response times or a CVE process.
